## 1. What is it about?

The Shapley–Scarf housing market: each participant initially owns one indivisible
object, wants one object, and reports a strict ranking. Money is unavailable.
The goal is to reallocate objects efficiently without rewarding dishonest reports.
Houses motivate the model; the introduction also discusses kidney exchange.

Here, “strategy” refers to preference-reporting behavior, “profitable” means a
preferred allocation, and “trading cycles” are exchange chains between owners.
These terms do not supply financial prices, investable returns or time-series cycles.

## 2. What does it find?

Theorem 1 states that for n>=3, TTC is uniquely characterized by:

- Pair-efficiency: no two participants can both improve by swapping their assignments.
- Respecting-improvement: making someone's endowed object more desirable to others
  cannot worsen that owner's assignment, evaluated using the owner's preferences.
- Endowment-position strategy-proofness: moving one's own object up/down in the
  reported ranking, while holding other objects' relative order fixed, cannot help.

The paper establishes a local-to-global characterization using adjacent swaps of
the endowed object. Theorem 2 shows a boundary: replacing respecting-improvement
with individual rationality still identifies TTC with three agents, but fails for
four or more. Other counterexamples show why weaker incentive conditions differ.
These are analytical claims under the specified allocation model, not empirical
financial findings. I have not independently certified the full proof.

## 3. Why does it make money, if it does?

There is no money or investment-profit objective in this model. Participants can
gain by receiving a more preferred object. Strategy-proofness concerns incentives
to misreport preferences; it does not guarantee a trading algorithm's profitability,
robustness, absence of market manipulation or protection against financial loss.

## 5. Can a strategy code be made?

**Yes for an allocation algorithm; no source-supported financial strategy.**
Section 3.1 gives an implementable TTC procedure:

1. Each remaining participant points to their favorite remaining object.
2. Each object points to its owner.
3. Find directed cycles; allocate each participant in a cycle the object they point to.
4. Remove those participants and objects and repeat until everyone is assigned.

The finite directed graph guarantees a cycle, and the procedure finishes within
n rounds. Code would require owners, complete strict rankings and input validation;
ties or additional constraints need separately specified extensions. Such a program
would compute allocations, not buy/sell signals. Building that unrelated tool was
not requested, so no algorithm or strategy file has been created.
