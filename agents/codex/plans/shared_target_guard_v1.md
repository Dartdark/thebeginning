# Shared Target Guard v1 — authorized research utility

User approved building the shared-input version on 2026-10-28. Build only under Codex paths; leave installed/live files, broker/VPS settings and all strategy allocations alone. This is operational tooling, not a new alpha strategy or a t6/Hunt restart. No economic trials.

One account alias/token and fixed evaluation target are configured once. A standard-library Python writer prompts for one manually verified balance per account, requires explicit account-flat confirmation, and atomically publishes an integer-only INI snapshot. A lock excludes concurrent writers. A separate PowerLanguage draft reads via the Windows profile API, validates schema/token/target/session/as-of/revision, and defaults to monitor-only. CurrentDate/CurrentTime require the PC and chart in Chicago time. 17:00 CT session rollover and 16:00–17:00 maintenance are explicit; weekend gates apply. Holiday calendar and broker reconciliation remain outside v1.

Retain the original per-chart target arithmetic. This reduces daily input edits; it is not an account-wide equity or flatten controller. Snapshot must reflect a flat account when published; v1 does not capture subsequent realized trades, manual trading, commissions posted later or other charts' open P&L. Session date freshness does not mean current account balance. No automatic resets on restart or invented balance reader.

Verification: atomic replacement/failure, concurrent-writer exclusion, cent precision/validation, immutable config and account separation, fixed 50K/150K targets, Chicago DST/rollover/weekends, missing/malformed/stale/future/token/target snapshots, mixed revision reads, restarts, target already met and exact long/short tick rounding at MNQ/NQ sizes. Linux tests validate the reference model/writer, not PowerLanguage compilation or Windows ABI/order cancellation. Save the compilation and paper-chart checklist; require independent Claude review before any installation.
